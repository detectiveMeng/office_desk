NiuMa-Workstation
一个「今天该干什么」的答案

左侧导航、右侧内容的单页工作台。以「今天要处理的」为入口，把散落在待办、项目、灵感里的东西收敛成一条每天可以照着走的行动线。

4 大模块 置顶 今天要处理的 蓝绿 · 商务克制 图表 纯 SVG/CSS 交付形态：单文件 HTML
01

概述与设计原则

OVERVIEW

要解决的问题

个人办公的痛点不在「记不住」，而在「该干的没干，干了的说不清」。任务列表人人都有，但真正卡住人的是三件事：昨天没做完的事悄悄消失了；多个项目并行时不知道每件事卡在哪；周末想复盘却想不起来这周精力花在哪。

所以这个工作台不追求功能多，而是把四个模块串成一条闭环：待办记录行动 → 挂到项目获得上下文 → 灵感承接临时想法 → 周复盘回收成果。

设计原则

① 答案优先于数据

顶部第一屏不是统计报表，而是「你现在该处理什么」。数据可视化放到模块内部，作为判断的辅助，不抢先。

② 任务不允许消失

任何未完成的任务都必须有一个明确归属：今天、某天、或逾期。顺延不是隐藏，而是一次带记录的位移。

③ 关联优于嵌套

任务只挂一个项目（单选），项目显示关联任务的完成率。不做多层级子任务，避免个人用户陷入维护结构的负担。

④ 一个页面一个动作

每个模块只有一个主操作（加任务 / 记灵感 / 加项目 / 写复盘），其余操作收进条目内联按钮，不铺满工具栏。

本次交付的核心决策

决策点结论理由
导航结构PC 左侧固定导航（252px）+ 右侧内容区；移动端导航降为底部 Tab桌面办公场景以「快速切换模块」为主，侧栏常驻比顶部 Tab 更省手
置顶区归属「今天要处理的」属于全局区，不单独做导航项，每个模块页顶部都可见（可折叠）它不是第五个模块，而是跨模块的警报层；做成导航项会被当成「又一个要维护的页面」
优先级模型四档：紧急重要 / 重要不紧急 / 紧急不重要 / 不急不重要沿用用户熟悉的四象限说法，比 P0–P3 更自解释；内部仍映射 P0–P3 便于排序
顺延机制只顺延日期，不复制任务；记录 postponeCount 与顺延流水复制会产生重复条目；顺延次数是「这件事一直没动」的强信号，值得显性化
项目-待办关系一对多，任务侧单选项目；项目侧只读汇总进度个人用户并行项目通常 3–8 个，无需多对多标签化
数据存储单文件 HTML + 浏览器本地存储（localStorage），附 JSON 导出/导入隐私优先、零运维、离线可用；如后续要跨设备再接资料来源库

模块一 · 今日待办

TODOS

工作台的主干。核心承诺只有一句：写下来的事，第二天不会消失。

页面结构（自上而下）

TODOS VIEW · 区块顺序
今日待办 10月18日 周日 · 4 件待办
筛选＋ 加任务
逾期任务（红）逾期 3 天 · 顺延 2 次顺延

今天要做的 B重要不紧急

明天 · 10/19未来任务 1
周三 · 10/21未来任务 2

字段定义

字段类型规则
标题文本必填，上限 80 字，超出省略号截断，hover 显示全文
优先级四选一紧急重要 / 重要不紧急 / 紧急不重要 / 不急不重要；默认「重要不紧急」
截止日期日期可选。留空即「待安排」，归入未来区的「无日期」组，不参与逾期判断
所属项目单选可选，下拉选择已建项目；选中后任务出现在该项目卡的关联任务下
备注多行文本可选，仅详情里展示，列表不显示
状态枚举todo / done；打勾即 done，记录 doneAt 时间戳
顺延次数整数系统维护，用户不可编辑；首次创建为 0
顺延流水数组每次顺延追加 {from, to, at}，详情里以时间轴展示

三种任务状态与视觉

逾期 · 标红

截止日期 < 今天且未完成。整行浅红底 + 左侧 3px 红条，日期文案显示「逾期 N 天」，行尾固定出现「顺延」按钮。不顺延也不消失，一直留在今日清单顶部。

今天 · 正常

截止日期 = 今天。白底、灰勾选框，行尾显示优先级标签。若该任务是从过去顺延来的，额外挂一枚「顺延 N 次」铅笔色小徽标。

未来 · 灰

截止日期 > 今天。按日期分组成折叠块，组头显示「明天 10/19 · 2 件」，文字颜色降一档，弱化存在感但随时可查。

交互细节

  • 快速添加：顶部输入框常驻，输入标题回车即建任务（默认「重要不紧急 + 今天 + 无项目」），随后可在行内补优先级/日期/项目，不需要先弹表单。
  • 完整表单：点「＋ 加任务」打开右侧抽屉（桌面）/ 底部弹层（手机），包含全部字段；从项目卡点「加一条」时项目字段预填且锁定。
  • 打勾：勾选框 44×44px 热区，点击后任务行 300ms 内淡出并移入「已完成」折叠区，顶部出现「已完成 · 撤销」提示条，5 秒内可撤销。
  • 改期：行内点日期胶囊直接弹出迷你日历，选完即改；若改到未来，自动移入对应日期分组。
  • 排序：今日清单固定按「逾期 → 优先级 P0→P3 → 截止日期 → 创建时间」排，不提供手动拖拽，避免排序成为新的维护负担。
  • 已完成：默认折叠，显示「本周已完成 N 件」，展开后按完成时间倒序，可按「今天/7 天内/更早」筛选。

字段类型规则

标签多选 + 可新建0–3 个。输入 # 触发已有标签联想，回车新建；标签全局共享同一套词表

交互细节

  • 零摩擦录入：进入模块时输入框自动聚焦，Ctrl/⌘ + Enter 保存，保存后清空并保留焦点，可连续记多条。
  • 标签筛选：标签行为单选筛选，顶部「全部 N」是默认态；标签数量为 0 的标签自动隐藏，超过 8 个标签时该行可左右滚动。
  • 卡片布局：桌面 3 列等高瀑布（按创建时间倒序，置顶优先）；手机上单列，正文超过 4 行折叠为「展开全文」。
  • 编辑与删除：卡片点击即进入行内编辑（不弹窗）；删除需二次点击确认（按钮变为「确认删除」），不做全局弹窗。
  • 空状态：无灵感时展示一行提示「想到什么就先记下来，不用管它有没有用」，配 2 条示例灵感，避免空白。

模块三 · 项目跟进

PROJECTS

这里回答的不是「做了什么」，而是「这件事现在到哪、下一步是谁、卡在哪」。项目与待办通过「所属项目」字段单向关联。

项目卡结构

PROJECT CARD · 六段式
项目名卡住了
现在 下一步 卡在
关联待办 1/2 · 逾期 1＋加一条

字段定义

字段类型规则
项目名文本必填，上限 40 字；重名允许但给出提示
现在到哪一步文本必填，一句话描述当前状态，上限 60 字。列表显示 2 行截断
下一步做什么文本必填，上限 60 字。这是项目卡最重要的字段——没有下一步的项目就是停滞项目
卡在哪文本 + 状态留空 = 没卡住；填写即视为阻塞，项目状态自动切换为「卡住了」，并进入置顶区
状态四选一进行中 卡住了 已完成 暂停；「卡住了」由卡点字段自动驱动，不手动选
关联待办反向计算只读。统计该项目下所有任务的完成数与总数，实时计算完成率
更新时间系统任一字段变更即刷新；卡片底部显示「更新于 X」；超过 7 天未更新打一枚「久未更新」浅标

关联待办的计算口径

进度条

完成率 = 已完成任务数 / 关联任务总数（含逾期、含无日期）。
关联任务为 0 时，进度条置灰并显示「暂无关联待办」，不显示 0%。

示例：2/4 完成 → 条形填充 50%，文案「关联待办 2/4」。

逾期提示

若关联任务中有逾期项，在进度文案后追加红色徽标「逾期 N」，并让整个项目卡左侧出现 3px 红条；同时该项目进入置顶区的「卡住项目」列表。

注意区分：「有逾期任务」与「项目卡住」是两件事——前者是任务延迟，后者是外部阻塞。视觉上前者用红条、后者用「卡住了」标签。

交互细节

  • 卡片内联编辑：「现在」「下一步」「卡在」三个字段点击即在原位变为输入框，失焦保存；不进入详情页就能完成日常更新。
  • 关联待办列表：卡片下方默认展示最近 3 条未完成关联任务（含日期与逾期状态），超出的收进「查看全部 N 条」，点击跳转今日待办并自动带上该项目筛选。
  • 加一条：从项目卡直接建任务，项目字段预填并锁定，建完回到项目卡，进度条即时更新。
  • 排序：默认「卡住 → 有逾期 → 最近更新」；顶部可切换「全部 / 进行中 / 卡住 / 已完成」。
  • 已完成项目：状态切为已完成时，卡片降低透明度并移入列表末尾，不删除，便于周末复盘回溯。

全局置顶 · 今天要处理的

ALERT BAR

跨模块的警报层，出现在每个模块页内容区最上方。只在有内容时完整展开，无事时收成一行轻提示。

收录规则

条目类型判定展示内容与动作
逾期任务未完成 且 截止日 < 今天任务标题 + 原定日期 + 「逾期 N 天」+ 顺延次数；动作：完成 / 顺延到明天
卡住的项目状态为「卡住了」项目名 + 卡点原文 + 下一步；动作：看待办 / 去处理（跳到项目卡编辑卡点）
反复顺延顺延次数 ≥ 2 且仍未完成并入逾期条目，额外挂一枚「已顺延 N 次」提示，文案引导「要不要拆小一点或直接删掉」

三种形态

有警报

红底浅填充 + 左侧红条。标题「今天要处理的」，副标「逾期 2 · 卡住 1」。右上角「全部顺延到明天」批量动作，需要二次确认（列出将被改期的任务名）。

全部清空

收缩为一行，左侧一个勾图标 + 文案「今天没有逾期，也没有卡住的项目」。不庆祝、不放礼花，保持安静。

手机端

默认展开前 3 条，剩余折叠为「还有 N 项」。每条右侧只保留最关键的一个按钮（逾期给「顺延」，卡住给「去处理」），其余收进「⋯」。

08

顺延与联动规则

RULES

Y2T：昨天没做完的自动挪到今天

用户不需要手动操作，规则由系统在每次打开页面时执行一次（加一个「上次运行日期」戳避免重复执行）。

未完成任务 且 截止日 < 今天 ▸ 截止日 改为 今天 ▸ 顺延次数 +1 ▸ 写入顺延流水 ▸ 出现在今日清单顶部（标红）
这里有一个容易做错的地方 如果「昨天没做完的自动挪到今天」，那任务就永远不逾期，也就永远标不红、进不了「今天要处理的」。
本设计的处理：自动顺延只发生在跨天时把旧任务带到今天，但保留一个 originalDate 原定日期字段。
判定逾期看的是 originalDate < 今天 且 顺延次数 ≥ 1——换句话说，今天到期的算「今天要做」，从过去挪过来的算「逾期但已顺延」，前者白底，后者红底并标注「原定 10/15 · 逾期 3 天 · 顺延 2 次」。这样既不丢任务，也不掩盖拖延。

规则清单

  • 自动顺延：任务未完成且 date < 今天 → date = 今天、postponeCount += 1、流水追加 {from, to: 今天, auto: true}。
  • 手动顺延：点击「顺延」→ 规则同上，但 auto: false，并给一条「已顺延到明天，第 N 次」的 toast，5 秒内可撤销。
  • 批量顺延：「全部顺延到明天」只作用于逾期任务，不动卡住项目；执行前确认弹窗列出任务名与件数。
  • 顺延达 3 次：该任务行出现一枚提示「这件事已顺延 3 次」，展开提供两个建议动作：「拆成两步」或「删除」。
  • 删任务：二次确认；若任务挂了项目，删除后项目进度自动重算，不留下幽灵计数。
  • 打勾完成：写入 doneAt = now；若关联项目，该项目卡的进度与逾期徽标即时刷新。
  • 改项目：任务从 A 项目改挂到 B，两边项目卡同时刷新，不做缓存。
  • 删项目：项目下的任务不删除，projectId 置空，任务退回「无项目」，并提示「已解除 3 个任务的关联」。
  • 卡点驱动状态：卡点字段从空 → 非空，项目状态自动置为「卡住了」并进入置顶区；清空卡点则回到「进行中」。
  • 周复盘只读：周复盘页不改任何原始数据，只在用户写总结时写入 weeklyNotes。

边界与后续迭代

SCOPE

本期明确不做

功能边界

  • 账号体系与多人协作——个人工作台，一人一份数据
  • 子任务与多级项目结构——避免维护成本超过收益
  • 提醒推送与日历同步——靠打开即见，不做系统通知
  • 附件与图片上传——超出轻量工作台范畴

结构边界

  • 不设第五个模块：置顶警报区不是模块，不占导航位
  • 不做全局搜索：四个模块的数据量在个人场景下不需要
  • 不做主题切换：白底蓝绿是唯一形态，减少选择
  • 不做甘特图：项目只看状态与卡点，不做时间排布
