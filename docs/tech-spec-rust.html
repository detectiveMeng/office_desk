NiuMa-Workstation
原生桌面实现方案

把产品设计说明落成可施工的原生桌面应用：Rust 编写、GPUI 渲染、SQLite 存储、主题配色可配置。领域口径（逾期 / 顺延 / 周复盘）与 v0.1 完全一致，仅替换运行形态与数据层。

语言 Rust 渲染 GPUI 存储 SQLite 平台 仅 Windows 可配置 主题 / 配色
01

技术选型与约束

STACK

选型结论

维度选择理由与代价
运行形态原生桌面应用（NiuMa-Workstation.exe）从「双击单文件 HTML」升级为「编译产物」。不再是 file:// 网页，无浏览器兼容负担
语言Rust（stable，edition 2024，MSRV 1.92）类型安全 + 内存安全 + 单测一等公民；领域层纯函数天然可 cargo test
UI 框架GPUI（锁版本）Zed 编辑器同款。像素级渲染 + 高质量文字排版，最贴合设计稿。组件层用现成的 gpui-component（60+ 组件，见右侧声明）
存储SQLite（rusqlite + bundled）真关系、事务原子写、外键、无容量上限；bundled 把 SQLite 编译进二进制，避免 Windows 上散落 DLL
日期chrono（NaiveDate/NaiveDateTime）替换原「YYYY-MM-DD 字符串」技巧，用真类型规避时区与比较错误；DB 内仍落 TEXT
配置TOML 文件 + 应用内设置页本期仅开放主题 / 配色；其余（优先级命名、周起始、快捷键）沿用默认值

硬约束

  • 仅 Windows：不承诺 macOS/Linux；GPUI 在 Windows 属前沿地带，需 MSVC 工具链 + 较新 stable Rust。
  • 离线可用：零网络请求，零外链，零遥测；所有数据只落本机 SQLite 文件。
  • 数据不丢：所有写操作走 SQLite 事务；提供 JSON 全量导出/导入；清空需二次确认。
  • 领域与渲染分离：领域层不得引用 GPUI / DB 连接，只输入输出数据结构，保证可被 cargo test 独立覆盖。
  • 可配置边界：只做主题/配色，不做优先级命名、周起始日、快捷键的可配——避免滑向无限配置。
GPUI 现状与风险（已更新） GPUI 自身仍标注 pre-alpha、API 无稳定性承诺、以 macOS 为核心平台（Windows 可用但更前沿）。但组件层生态已成熟：gpui-component（Longbridge 的 gpui-kit 一部分，60+ 桌面组件、已发 20+ 版本，v0.8.0 ≈ 2026-10）、另有 adabraka-ui（85+ 组件，shadcn/ui 风格）等可选。因此 标准控件（按钮/输入框/取色器/表格/弹层…）不再自绘，直接引组件库；自绘只剩四类图表。
应对：① 用 gpui-kit 统一依赖，由它锁定匹配的 gpui 版本，不在 Cargo.toml 里浮动 branch = "main"；② 领域层零 GPUI 依赖，框架换或不换都不影响核心逻辑。

03

数据层（SQLite）

STORAGE

连接与运行参数

单连接、Mutex 保护（个人单窗口应用无需连接池），启动时执行 PRAGMA foreign_keys = ON; PRAGMA journal_mode = WAL;。数据库文件与配置同目录：%APPDATA%\NiuMa-Workstation\。

表结构（DDL）

-- 1) 任务：status ∈ todo|done；priority ∈ 0..3（映射 P0..P3）
CREATE TABLE todos (
  id                TEXT PRIMARY KEY,
  title             TEXT NOT NULL,
  priority          INTEGER NOT NULL DEFAULT 1,
  date              TEXT,                     -- YYYY-MM-DD，NULL=待安排
  original_date     TEXT,                     -- 逾期判定依据，永不改
  project_id        TEXT REFERENCES projects(id) ON DELETE SET NULL,
  status            TEXT NOT NULL DEFAULT 'todo',
  done_at           TEXT,
  note              TEXT NOT NULL DEFAULT '',
  postpone_count    INTEGER NOT NULL DEFAULT 0,
  created_at        TEXT NOT NULL
);

-- 2) 顺延流水（原 JSON 数组拆成子表）
CREATE TABLE postpone_log (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  todo_id    TEXT NOT NULL REFERENCES todos(id) ON DELETE CASCADE,
  from_date  TEXT, to_date TEXT, at TEXT, auto INTEGER
);

-- 3) 项目：status ∈ active|blocked|done|paused
CREATE TABLE projects (
  id        TEXT PRIMARY KEY,
  name      TEXT NOT NULL,
  current   TEXT NOT NULL DEFAULT '',
  next      TEXT NOT NULL DEFAULT '',
  blocker   TEXT NOT NULL DEFAULT '',
  status    TEXT NOT NULL DEFAULT 'active',
  updated_at TEXT NOT NULL
);

-- 4) 卡点流水（周复盘「卡点汇总」用）
CREATE TABLE blocker_log (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  text       TEXT, start_at TEXT, end_at TEXT
);

-- 5) 灵感 / 周复盘 / 元数据
CREATE TABLE notes (
  id TEXT PRIMARY KEY, content TEXT NOT NULL,
  tags TEXT NOT NULL DEFAULT '[]',   -- JSON 数组
  pinned INTEGER NOT NULL DEFAULT 0, created_at TEXT, updated_at TEXT
);
CREATE TABLE weekly_reviews (
  week_start TEXT PRIMARY KEY, good TEXT, watch TEXT, focus TEXT, updated_at TEXT
);
CREATE TABLE meta (
  key TEXT PRIMARY KEY, value TEXT   -- schema_version / last_run_date / seeded_at
);
数组落库的两套做法，取后者 postpone_log / blocker_log 原本是 JSON 数组，直接 serde_json 存 TEXT 也能跑，但无法用 SQL 过滤、迁移也麻烦。拆成子表 + 外键 ON DELETE CASCADE，删任务/删项目自动清流水，无孤儿数据。

内存镜像与读写

启动时 SELECT 全量载入 DataSnapshot（个人数据量级下全量载入最省心），渲染只读快照；每次动作在事务里 INSERT/UPDATE/DELETE 后回写快照并 cx.notify()。周复盘四类统计一律由领域层从快照实时派生，不落库（与 v0.1 一致）。

迁移

const MIGRATIONS: &[&str] = &[/* v1 = 上面的 DDL */, /* v2 = 将来增量 ALTER ... */];

// 用 meta 里的 schema_version 记录当前版本，启动时按序执行高于当前版本的迁移
fn migrate(conn: &Connection) -> Result<()> {
    let v = get_meta(conn, "schema_version")?.unwrap_or(0);
    for (i, sql) in MIGRATIONS.iter().enumerate().skip(v as usize) {
        conn.execute_batch(sql)?;
        set_meta(conn, "schema_version", &(i + 1).to_string())?;
    }
    Ok(())
}

导出 / 导入

导出

生成 NiuMa-Workstation-YYYY-MM-DD.json，结构 { app, version, exported_at, data }，data 即四张表 + 流水的规范化 JSON；写到用户选择的位置（原生文件对话框，无网络）。

导入

读 JSON → 校验 app 标识与字段 → 弹摘要「将导入 N 任务 / M 项目 / K 灵感，覆盖当前数据」→ 确认后在单事务内清空并重灌。兼容 v0.1 网页导出的 JSON（backup.rs 做字段映射）。

领域逻辑层

DOMAIN

本章口径与 v0.1 逐条一致，只是从 ES5 纯函数翻译成 Rust 纯函数。可用 cargo test 直接回归，不再靠肉眼比对页面数字。

4.1 逾期判定（唯一口径）

enum Bucket { Done, Overdue, Today, Future, Someday }

fn bucket(t: &Todo, today: NaiveDate) -> Bucket {
    if t.status == Status::Done  { return Bucket::Done; }
    let Some(date) = t.date else { return Bucket::Someday; };
    if date > today { return Bucket::Future; }
    match t.original_date {
        Some(od) if od < today => Bucket::Overdue,
        _ => Bucket::Today,
    }
}

fn overdue_days(t: &Todo, today: NaiveDate) -> i64 {
    t.original_date.map(|od| (today - od).num_days().max(0)).unwrap_or(0)
}

4.2 自动顺延（Y2T）

fn run_auto_rollover(s: &mut DataSnapshot, today: NaiveDate, now: NaiveDateTime) -> bool {
    if s.meta.last_run_date == Some(today) { return false; }
    let mut changed = false;
    for t in s.todos.iter_mut().filter(|t| t.status == Status::Todo) {
        if let Some(d) = t.date { if d < today {
            t.postpone_log.push(PostponeEvent { from: Some(d), to: today, at: now, auto: true });
            t.postpone_count += 1;
            t.date = Some(today);          // original_date 不变 → 仍标红
            changed = true;
        }}
    }
    s.meta.last_run_date = Some(today);
    changed                                    // true 时执行一次 save()
}
隔 N 天不打开 「原定 10/10，10/15 打开」只记一次顺延（from 10/10 → to 今天），逾期天数用 today - original_date 表达。语义与 v0.1 完全一致。

4.3 排序与分组

// 排序权重：逾期优先 → 优先级 → 原定日期更早 → 创建更早
fn sort_for_today(list: &mut [Todo], today: NaiveDate) {
    list.sort_by(|a, b| {
        (bucket(a, today) == Bucket::Overdue as u8)
            .cmp(&(bucket(b, today) == Bucket::Overdue as u8))   // overdues 在前
            .then_with(|| a.priority.cmp(&b.priority))
            .then_with(|| a.original_date.cmp(&b.original_date))
            .then_with(|| a.created_at.cmp(&b.created_at))
    });
}

4.4 项目进度与状态

struct Progress { total: usize, done: usize, overdue: usize, rate: Option<f64> }

fn progress(p: &Project, todos: &[Todo], today: NaiveDate) -> Progress {
    let rel: Vec<_> = todos.iter().filter(|t| t.project_id.as_deref() == Some(p.id.as_str())).collect();
    let done = rel.iter().filter(|t| t.status == Status::Done).count();
    let overdue = rel.iter().filter(|t| bucket(t, today) == Bucket::Overdue).count();
    Progress { total: rel.len(), done, overdue,
              rate: (rel.len() > 0).then(|| done as f64 / rel.len() as f64) }
}

// 状态由卡点驱动，不允许手动设 blocked
fn sync_status(p: &Project) -> Status {
    match p.status { Status::Done | Status::Paused => p.status,
        _ => if !p.blocker.trim().is_empty() { Status::Blocked } else { Status::Active } }
}

4.5 周复盘口径

同 v0.1：本周完成 / 完成率（分母 = 本周到期 ∪ 本周完成）/ 优先级分布 / 精力分布 / 一周节奏 / 顺延事件（按 postpone_log.at 计数）/ 卡点汇总（取 blocker_log 与本周交集）。全部由 stats.rs 纯函数实现，用 v0.1 的种子数据做回归断言：

assert_eq!(w.done_count, 11);
assert_eq!(round(w.done_rate * 100.0), 85);   // 11/13 = 84.6%
05

渲染层（GPUI）

RENDER

窗口与根组件

// main.rs：加载配置 → 打开 DB → 跑迁移/种子 → 启动 GPUI
gpui::Application::new().run(move |cx| {
    let state = cx.new_model(|_| AppState::init(config, db));
    cx.activate_window(cx.open_window(WindowOptions::default(), |cx| {
        cx.new_view(|cx| Root::new(state.clone(), cx))
    })?);
})?;

根组件渲染左导航（252px）+ 内容区；置顶区（今天要处理的）常驻在内容区顶部，四个视图容器随 ui.view 切换显隐。GPUI 是保留模式：视图只读 AppState，不手工拼 DOM。

刷新机制（替代 v0.1 的 refreshAll）

v0.1 靠「全量重建 innerHTML + 事件委托」规避刷新；GPUI 下这条手工纪律退化为框架能力——动作层改完 AppState 后调用一次 cx.notify()，绑定到该 Model 的视图自动重渲染。两条红线仍保留：

  • 视图不写状态：视图函数只读 state，产出元素树，不直接改数据、不碰 DB。
  • 动作是唯一写入口：所有改动经 actions.rs，统一「改快照 → 事务落库 → cx.notify()」。
GPUI 下的焦点与滚动 保留模式下 GPUI 自行管理节点复用与焦点，不存在 v0.1 担心的「全量重渲染丢焦点/跳滚动」问题；行内编辑切换输入框时由 ui.editing 控制焦点，不必再手工恢复。

视图骨架

impl Root {

06

可视化实现

CHARTS

标准控件（按钮/输入框/表格/抽屉/弹层）直接用 gpui-component；只有四类图表需要自绘——实现 GPUI 自定义元素，在其 paint 回调里用画布原语绘制；颜色全部取自当前 Theme，随主题切换即时刷新。

图表绘制方式
优先级分布 · 横条4 条 rect，条长 = value/max * 可用宽（max 取四项最大，非总数）；有值至少 6px；条尾 text 数值
精力分布 · 环形用弧段 path.arc() 分段填充，起止角按累计比例；100% 时整圆闭合（不出现缺口）；中心文本为完成总数
一周节奏 · 柱状7 根柱，高度 = value/max * H；无数据日画 2px 基线；今天高亮（主题强调色）
进度条 / 计数条不画布，用 GPUI 布局：外层 overflow-hidden + 内层按百分比定宽，配 transition

环形图示意（自定义 Element 的 paint）

impl Element for DonutChart {
    fn paint(&mut self, bounds: Bounds<Pixels>, cx: &mut Window) {
        let theme = &*cx.theme(); // 当前主题颜色
        let (cx0, cy0) = bounds.center();
        let r = bounds.size.width.min(bounds.size.height) / 2.0 - STROKE/2.0;
        let total: f64 = self.data.iter().map(|d| d.value).sum();
        let mut acc = -90.0;                 // 从 12 点方向
        for d in &self.data {
            let sweep = d.value / total * 360.0;
            cx.paint_path(Path::arc((cx0, cy0), r, acc, acc + sweep)
                .stroke(d.color, StrokeWidth(STROKE)));
            acc += sweep;
        }
    }
}
数值文字仍是文本 图表下方保留一张可读的数值列表（与 v0.1 无障碍规范一致），不单靠颜色/图形传达信息；圈心「本周完成 N」用 text 绘制。

应用内设置页与热重载

  • 设置页：导航底部入口，浅色/深色/自定义三选 + 色板（每个 token 一个取色器，用 gpui-component 的 color picker）。
  • 实时预览：改色即时写入 Settings 并 cx.set_global(theme) + cx.refresh()，全窗口立刻换色。
  • 持久化：确认后写回 config.toml（保留注释与未改项）；默认色与用户色分离，用户色只存「相对覆盖」。
浅色 / 深色两套，不做"任意主题市场" 深色不是简单反色，背景/纸/描边/浅底需成组调整以保证对比度；先把 light/dark 两套默认打磨好，custom 仅作为进阶覆盖。避免一开始就做完整主题系统导致范围失控。
