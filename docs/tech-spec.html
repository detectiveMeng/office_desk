01

技术选型与约束

STACK

选型结论

不做框架选型，本身就是结论：原生 HTML + 内联 CSS + 内联 ES5 脚本，零依赖、零构建、零请求。个人办公工作台的交互复杂度（4 个模块、约 30 个动作、两处统计图表）远未到需要引入虚拟 DOM 的程度；而引入任何构建或依赖，都会破坏「单文件下载即用、离线可用」这一硬需求。

维度选择理由与代价
运行形态单文件 .html，双击打开（file:// 协议）无需服务器；代价：不能使用 ES Module 的 import（file:// 下会被 CORS 拦截），也无需使用
语言级别ES5 语法（var / function / 无箭头函数无模板字符串）兼容老旧内核与企业内网浏览器；代价：拼接 HTML 稍啰嗦，用 h() 辅助函数与数组 join 缓解
框架无改用「数据变更 → refreshAll() 全量重渲染当前视图」的粗粒度更新。单视图 DOM 节点量 < 300，全量重建耗时 < 8ms，人眼无感
样式内联 <style> + CSS 变量设计令牌集中在 :root，改配色只改 8 个变量
图表手写内联 SVG不引 D3/ECharts；四类图表均可由字符串模板直接生成，天然随主题色变化
图标内联 SVG path，统一 24×24 / 1.6px 线宽不用 emoji（跨平台渲染不一致、无法着色、无法对齐基线）
存储localStorage，命名空间 wb_office_*同步 API、容量 5MB 足够；代价：需自行处理 JSON 解析失败与版本迁移（见 03 章）
日期处理自写 DateUtil，纯字符串 + 本地时区不引 dayjs；全程使用 YYYY-MM-DD 字符串做日期键，规避时区导致「刚过 0 点日期就错一天」的经典坑

硬约束（不可协商）

  • 零外部请求：不得出现 http(s)://、CDN、外链字体、外链图片。页头配图必须是内联 SVG。
  • 单文件：CSS 与 JS 全部内联，目标 1 个 .html，体积上限 150KB。
  • 移动端可用：窄屏 320px 起不出现横向滚动；输入框字号 ≥ 16px（避免 iOS 聚焦缩放）；点击热区 ≥ 44px。
  • 数据不丢：刷新、关闭、重开数据一致；提供 JSON 导出/导入；清空需二次确认。
  • 无环调用：渲染函数之间严禁互调，统一经 refreshAll() 调度（详见 05 章）。
为什么坚持 ES5 这套代码的交付对象是「用户保存在电脑里、可能三年后才打开的单个 HTML」。使用箭头函数、可选链、?? 等现代语法会让它在旧内核里直接白屏且没有任何错误提示。ES5 多写 10% 的字符，换的是「任何时候双击都能开」。

整体架构

ARCHITECTURE

分层

严格四层单向依赖，上层可调下层，下层绝不回调上层。这是避免「渲染函数互调导致栈溢出」的根本手段。

03

数据层

STORAGE

存储键设计

Key内容说明
wb_office_data_v1整个 store 的 JSON（todos + projects + notes + reviews + meta）单一键，原子写入，避免多键不同步
wb_office_ui_v1少量视图偏好（上次所在 Tab、置顶区是否折叠）丢失无影响，读写都包 try/catch
为什么用单键而不是分表多键 多键方案下，一次「完成任务 + 项目进度变化」要写两处，一旦第二处写入失败（配额满）就会产生跨表不一致。单键序列化后一次 setItem 成功或失败，天然原子。数据量估算：1000 条任务约 260KB，远低于 5MB 上限。

Schema 版本迁移

首版 schemaVersion = 1，但迁移框架现在就埋好——个人工具最常见的翻车是「半年后加了个字段，老数据读进来是 undefined，页面某处静默空白」。

function migrate(d){
  var v = d.meta && d.meta.schemaVersion || 0;
  if (v < 1) {
    // v0（无版本号）→ v1：补齐 originalDate、postponeLog
    (d.todos || []).forEach(function(t){
      if (!t.originalDate) t.originalDate = t.date || null;
      if (!t.postponeLog)  t.postponeLog  = [];
      if (typeof t.postponeCount !== 'number') t.postponeCount = t.postponeLog.length;
    });
    d.meta = d.meta || {}; d.meta.schemaVersion = 1;
  }
  // 防御：任何缺失集合补空数组，杜绝后续 .filter 崩溃
  d.todos = d.todos || []; d.projects = d.projects || [];
  d.notes = d.notes || []; d.reviews = d.reviews || {};
  return d;
}

04

领域逻辑层

DOMAIN

本章是整个方案最关键的部分：逾期判定、自动顺延、分组排序、项目进度、周复盘口径。全部实现为纯函数（输入数据，输出结果，不改入参、不碰 DOM），因此可以脱离页面直接用 Node 跑用例验证。

4.1 逾期判定的唯一口径

产品设计里提出「自动顺延到今天，但依然标红」。落地为两个字段各管一件事：

字段含义谁写
date现在的截止日，决定「归到哪一天」。自动顺延后 = 今天用户改期 / 顺延逻辑
originalDate最初定的截止日，永不修改，是逾期判定的唯一依据创建时写入，之后只读
 
// 判定的三态：逾期 / 今天 / 未来 / 待安排
Todo.bucket = function(t, today){
  if (t.status === 'done')    return 'done';
  if (!t.date)                return 'someday';   // 无日期，不参与逾期
  if (t.date > today)         return 'future';
  // date <= today：是否由过去挪来？
  return (t.originalDate && t.originalDate < today) ? 'overdue' : 'today';
};

Todo.overdueDays = function(t, today){
  if (!t.originalDate) return 0;
  var d = DateUtil.diffDays(today, t.originalDate);
  return d > 0 ? d : 0;
};
边界：同一天内改期 用户把今天到期的任务改成昨天（date = 昨天），originalDate 仍是今天 → 不判逾期，但 date < today。为避免出现「既不逾期也不在今天」的黑洞，bucket 对 date <= today 一律归入 today 或 overdue，保证今日清单不漏条目。

4.2 自动顺延（Y2T）

时机：每次页面加载，在首次渲染之前执行一次。用 meta.lastRunDate 去重，避免同一天内多次刷新反复 +1。

Todo.runAutoRollover = function(store, today){
  var changed = false;
  if (store.meta.lastRunDate === today) return changed;    // 当天已跑过

  store.todos.forEach(function(t){
    if (t.status !== 'todo') return;
    if (!t.date || t.date >= today) return;              // 未来 / 无日期不动

    t.postponeLog.push({ from: t.date, to: today, at: DateUtil.now(), auto: true });
    t.postponeCount += 1;
    t.date = today;                                          // originalDate 保持不变 → 仍然标红
    changed = true;
  });

  store.meta.lastRunDate = today;
  return changed;   // true 时触发一次 save()
};
跨越 N 天没打开 任务原定 10/10，用户 10/15 才打开。无论中间隔了几天，只记一次顺延（from 10/10 → to 今天），而不是循环 +5 次。原因：顺延次数的语义是「我几次决定往后推」，不是「过了几个自然日」。若想表达拖延程度，用逾期天数（今天 − originalDate）已经足够。

4.3 今日清单的排序与分组

// 排序权重：逾期优先 → 优先级 → 原定日期更早 → 创建更早
var PRI_W = { P0:0, P1:1, P2:2, P3:3 };

Todo.sortForToday = function(list){
  return list.slice().sort(function(a, b){
    var oa = Todo.bucket(a, TODAY) === 'overdue' ? 0 : 1;
    var ob = Todo.bucket(b, TODAY) === 'overdue' ? 0 : 1;
    if (oa !== ob) return oa - ob;
    var pa = PRI_W[a.priority], pb = PRI_W[b.priority];
    if (pa !== pb) return pa - pb;
    var da = a.originalDate || '9999-99-99', db = b.originalDate || '9999-99-99';
    if (da !== db) return da < db ? -1 : 1;
    return a.createdAt < b.createdAt ? -1 : 1;
  });
};

// 未来任务按 date 字符串分组（YYYY-MM-DD 字典序 == 时间序）
Todo.groupFuture = function(list){
  var map = {}, order = [];
  list.forEach(function(t){
    var k = t.date || '';
    if (!map[k]) { map[k] = []; order.push(k); }
    map[k].push(t);
  });
  order.sort(function(a, b){
    if (!a) return 1;            // 无日期排最后
    if (!b) return -1;
    return a < b ? -1 : 1;
  });
  return order.map(function(k){ return { date:k, items: map[k] }; });
};

用 YYYY-MM-DD 字符串排序而非 Date 对象比较，是为了彻底避开时区：字符串字典序在补零格式下与时间序完全一致，且比较开销更低。

4.4 项目进度与状态

Project.progress = function(p, todos, today){
  var rel = todos.filter(function(t){ return t.projectId === p.id; });
  var done = rel.filter(function(t){ return t.status === 'done'; }).length;
  var overdue = rel.filter(function(t){ return Todo.bucket(t, today) === 'overdue'; }).length;
  return {
    total: rel.length, done: done, overdue: overdue,
    rate: rel.length ? done / rel.length : null,   // null 表示「暂无关联」，UI 显示置灰而非 0%
    items: rel
  };
};

// 状态由卡点字段驱动，不允许手动设 blocked
Project.syncStatus = function(p){
  if (p.status === 'done' || p.status === 'paused') return p.status;
  return (p.blocker && p.blocker.trim()) ? 'blocked' : 'active';
};
为什么 blocked 不让手选 手选会产生「状态说卡住、但没写卡在哪」的空卡点，这种条目放进置顶区等于噪音。填写卡点即自动 blocked，清空即回到 active，一个字段同时解决状态与原因，也顺便强制用户把问题说清楚。

4.5 周复盘口径

这一节的每个数字都做了实算校验（示例数据见 10 章），避免交付时出现「图上有 12 件、列表只有 11 条」的信任崩塌。

指标口径（精确到实现）示例值
本周完成status==='done' && doneAt ∈ [周一 00:00, 周日 23:59]，按本地日期字符串比较11 件
完成率分母 = 本周到期的任务 ∪ 本周完成的任务（去重）；分子 = 分母中 done 的数量11 / 13 = 84.6%
优先级分布对「本周完成」按 priority 分四档计数P0 4 · P1 3 · P2 4 · P3 0
精力分布对「本周完成」按 projectId 计数，null 合并为「其他」；取前 5 个项目 + 其他首页改版 3 · 其他 3 · Q3 3 · 博客 2
一周节奏周一至周日，每日 doneAt 落在该日的完成数0 · 2 · 2 · 1 · 2 · 1 · 2
顺延次数本周内发生的 postponeLog[].at 事件计数（非 postponeCount 求和，避免历史累积重复计算）2 件各顺延 2 次
卡点汇总遍历 blockerLog，取与本周有交集的区间；endAt 为空 = 未解除1 未解除 / 2 已解除
 
Stats.weekRange = function(weekStart){        // 周一为一周起点
  return { start: weekStart, end: DateUtil.addDays(weekStart, 6) };
};

Stats.week = function(store, weekStart){
  var r = Stats.weekRange(weekStart);
  var inWeek = function(d){ return d && d >= r.start && d <= r.end; };

  var done = store.todos.filter(function(t){
    return t.status === 'done' && inWeek(DateUtil.dayOf(t.doneAt));
  });

  // 分母：本周到期 ∪ 本周完成
  var ids = {};
  store.todos.forEach(function(t){
    if (inWeek(t.date) || (t.doneAt && inWeek(DateUtil.dayOf(t.doneAt)))) ids[t.id] = true;
  });
  var denom = Object.keys(ids).length;
  var denomDone = store.todos.filter(function(t){
    return ids[t.id] && t.status === 'done';
  }).length;

  return {
    range: r,
    doneCount: done.length,
    doneRate: denom ? denomDone / denom : null,
    byPriority: Stats.countBy(done, 'priority'),
    byProject: Stats.byProject(done, store.projects),
    byDay: Stats.byDay(done, r),
    postponeEvents: Stats.postponeIn(store.todos, r),
    blockers: Stats.blockers(store.projects, r)
  };
};
05

渲染层与刷新机制

RENDER

单一刷新入口（防环核心）

所有数据变更结束后，只调用 refreshAll()。渲染函数彼此之间没有任何调用关系，都只读 store、只写自己的容器。renderAll() 的顺序固定，且每个函数内部不再触发别的渲染。

// ✅ 唯一的渲染调度点
function refreshAll(){
  refreshAlert();       // 置顶区（跨模块可见）
  refreshNavBadge();    // 导航上的待办/逾期计数

  switch (ui.view) {
    case 'todos':    refreshTodos();    break;
    case 'notes':    refreshNotes();    break;
    case 'projects': refreshProjects(); break;
    case 'weekly':   refreshWeekly();   break;
  }
}

// ❌ 禁止：refreshTodos 内部调用 refreshAlert 或 refreshProjects
//    需要联动时，改数据后调 refreshAll()，由它统一按序重算
必须守住的三条线 ① 渲染函数不读 DOM 判断状态，只读 store / ui；
② 渲染函数不写 store，只写自己容器的 innerHTML；
③ 任何 renderXxx 内出现另一个 renderXxx( 调用，即视为缺陷，代码自检阶段直接拦下。

渲染策略：局部全量替换

每个视图有一个固定容器（如 #view-todos），刷新时整体重建其 innerHTML。用字符串拼接而非 DOM API 逐节点创建，性能与可读性都更好。

function h(tag, attrs, children){        // 极简模板助手
  var s = '<' + tag;
  for (var k in attrs) {
    if (attrs[k] === null || attrs[k] === undefined || attrs[k] === false) continue;
    s += ' ' + k + '="' + esc(attrs[k]) + '"';
  }
  return s + '>' + (children || '') + '</' + tag + '>';
}

// 用户输入必须过 esc()，防 XSS 也防引号破坏结构
function esc(v){
  return String(v == null ? '' : v)
    .replace(/&/g, '&amp;').replace(/</g, '&lt;')
    .replace(/>/g, '&gt;').replace(/"/g, '&quot;');
}
全量替换的两个坑 焦点丢失：行内编辑时若触发全量重渲染，输入框会失焦、光标回到开头。处理方式是——编辑态不触发 refreshAll，只在失焦提交时改数据再刷新；或刷新后按 ui.editing 恢复焦点并把光标移到末尾。
滚动跳动：刷新前记录当前视图 scrollTop，刷新后写回。

可视化实现

CHARTS

四类图表全部内联 SVG 字符串生成，视口宽度固定、width:100% 自适应，不依赖 JS 测量 DOM（因此无需 resize 监听，也无需 getBBox）。

6.1 优先级分布 · 横向条形

四条固定高度 10px、圆角 3px 的矩形。条长 = value / max * 可用宽度；最大值取四项中的最大件数，不取总数，否则四项都很短。条尾标注数值，用 text-anchor:start 定位在条形末端右侧 6px。

Charts.priorityBars = function(byPriority){
  var rows = [
    { key:'P0', label:'紧急重要',   color:'#c0392b' },
    { key:'P1', label:'重要不紧急', color:'#e08e3c' },
    { key:'P2', label:'紧急不重要', color:'#0d9488' },
    { key:'P3', label:'不急不重要', color:'#9aadaa' }
  ];
  var W = 300, LABEL = 64, BAR = W - LABEL - 34;   // 右侧留 34px 放数字
  var max = Math.max(1, Math.max.apply(null, rows.map(function(r){ return byPriority[r.key] || 0; })));

  var body = rows.map(function(r, i){
    var v = byPriority[r.key] || 0;
    var w = v ? Math.max(6, Math.round(v / max * BAR)) : 0;   // 有值至少 6px，避免看不见
    var y = i * 26 + 6;
    return '<text x="0" y="' + (y + 8) + '" class="ck-lbl">' + r.label + '</text>' +
           '<rect x="' + LABEL + '" y="' + y + '" width="' + w + '" height="10" rx="3" fill="' + r.color + '" opacity=".86"/>' +
           '<text x="' + (LABEL + w + 6) + '" y="' + (y + 9) + '" class="ck-val">' + v + '</text>';
  }).join('');

  return '<svg viewBox="0 0 300 ' + (rows.length * 26 + 12) + '" class="chart" role="img">' + body + '</svg>';
};

6.2 精力分布 · 环形图

不画弧线 path，改用 stroke-dasharray 圆环 + rotate 偏移：每一段就是一个 <circle>，周长 C = 2πr，段长 = value/total*C，起始角 = 前面所有段的累计角度。

var R = 38, CIRC = 2 * Math.PI * R;      // ≈ 238.76

var acc = 0;
var segs = data.map(function(d, i){
  var len = d.value / total * CIRC;
  var rot = -90 + acc / CIRC * 360;         // -90 = 从 12 点方向开始
  acc += len;
  return '<circle r="' + R + '" fill="none" stroke="' + d.color + '" stroke-width="16" ' +
         'stroke-dasharray="' + len.toFixed(2) + ' ' + (CIRC - len).toFixed(2) + '" ' +
         'transform="rotate(' + rot.toFixed(2) + ')"/>';
}).join('');
为什么不用 path 弧线 d="M … A …" 需要三角函数算起止点，且 100%（单项目）时起止点重合会导致弧线消失，必须特判。dasharray 方案天然支持 100%，数学也只有乘除，代码量少一半。

6.3 一周节奏 · 柱状图

7 根柱子，x = i * (W/7) + 偏移，高度 = value/max*H。三条水平网格线用固定值绘制，无数据的日子也画一个 2px 高的基线条，让「这天没干活」可视化，而不是柱子凭空消失。

6.4 进度条与热力小格（CSS 实现）

项目卡进度条、置顶区计数条这类「单值比例」用纯 CSS：外层固定高度 overflow:hidden，内层 width 百分比 + transition:width .3s。不用 SVG，减 DOM 数量。

图表规范汇总

项目规范

事件委托（唯一监听入口）

因为视图是全量重建的，逐个绑定监听会随刷新反复泄漏。方案是只在 #app 上绑一次 click / change / keydown，靠 data-act 属性分发。

document.addEventListener('click', function(e){
  var el = closest(e.target, '[data-act]');
  if (!el) return;
  var act = el.getAttribute('data-act');
  var id  = el.getAttribute('data-id');

  switch (act) {
    case 'todo-toggle':  Actions.toggleTodo(id);        break;
    case 'todo-postpone':Actions.postponeOne(id);       break;
    case 'todo-del':     Actions.askDeleteTodo(id);     break;
    case 'rollover-all': Actions.postponeAllOverdue();   break;
    case 'proj-edit':    Actions.beginInlineEdit(el);    break;
    case 'nav':          Actions.switchView(id);         break;
    // …共约 26 个
  }
});

动作方法命名规则：data-act 用「对象-动作」短横线格式，与 Actions 中的方法一一对应，便于排查「点了没反应」是渲染漏了 data-act 还是动作没注册。

function withUndo(label, applyFn, undoFn){
  applyFn();
  refreshAll(); Store.save();
  UI.toastUndo(label, function(){ undoFn(); refreshAll(); Store.save(); });
}

风险处理
localStorage 被清空每次启动检查 meta.seededAt；数据为空且从未播种 → 写入示例数据并标记，避免用户误以为数据丢失

所有数据仅存在用户本机浏览器，不上传、不埋点、不发任何网络请求（可用 DevTools Network 面板验证「零请求」）。页面若部署到公网，链接持有者可打开页面但看不到任何本机数据。不宣称加密——localStorage 是明文，仅可作为个人工具的便利性存储。
